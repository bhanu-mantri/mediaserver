How the home media server works

You search for a title, and it downloads through Surfshark, gets renamed and filed, and appears in Jellyfin ready to watch. This page shows each component, how they connect, where files go, and what was learned while setting it up.

Life of a request

What happens between clicking Request and pressing Play. Tested end-to-end with Night of the Living Dead (1968, public domain).

  1. You request a title Seerr

    Search in Seerr (TMDB data). You're the admin, so the request is approved automatically.

  2. Seerr hands it to the right manager Radarr / Sonarr

    Movies go to Radarr, series to Sonarr (anime is detected and gets series type anime). Quality profile HD-1080p; library folder chosen per type.

  3. The manager asks Prowlarr for releases Prowlarr

    Radarr/Sonarr query the indexers Prowlarr synced to them (Torznab). Prowlarr fans the search out to every indexer at once.

  4. Searches leave through the VPN gluetun :8888

    The ISP blocks most torrent sites, so Prowlarr's global proxy is gluetun's HTTP proxy. Cloudflare-protected sites go through FlareSolverr, which also lives in the VPN container.

  5. Best release is grabbed qBittorrent

    The manager scores results (quality, size, seeders, custom formats) and sends the winner to qBittorrent with a category: movies or tv.

  6. Download over the tunnel /data/torrents

    qBittorrent is bound to tun0; peers only ever see the Surfshark IP. Files land in /data/torrents/<category>. Seeding stops at ratio 1.0.

  7. Import, rename, file it /data/media

    When complete, the manager copies the file into the library with a clean name, e.g. Night of the Living Dead (1968)/… Bluray-1080p.mkv, plus any subtitle files. Bazarr then fetches English subtitles if none are included and saves them as .en.srt next to the video.

  8. Jellyfin picks it up Jellyfin

    The manager tells Jellyfin to refresh the library; Jellyfin fetches metadata and artwork. Seerr's periodic scan then marks the request Available.

  9. You press play any device

    Stream from localhost:8096 on this PC or 192.168.0.102:8096 from the Jellyfin app on a phone or TV on the same Wi-Fi.

Network & VPN topology

All containers share one Docker bridge network and find each other by container name (Docker's built-in DNS). Three of them share gluetun's network namespace, so their only route to the internet is the WireGuard tunnel.

Storage layout

One host folder is mounted as /data in every container that touches files, so a path means the same thing everywhere. Mismatched paths are the most common reason imports fail.

C:\Users\Bhanu\projects\mediaserver\

├── docker-compose.yml # the whole stack ├── .env # secrets: VPN key, passwords ├── SETUP.md # setup log & how-tos ├── config\ # each app's settings (back up!) └── data\ # = /data in containers ├── torrents\ # qBittorrent writes here │ ├── movies\ │ └── tv\ └── media\ # Jellyfin reads here ├── movies\ # Radarr → "Movies" └── tv\ # Sonarr → "Shows"

Why files are copied, not moved

Normally the *arr apps hardlink: the same file appears in torrents/ (still seeding) and media/ without using extra space. Docker Desktop's Windows bind mounts can't create hardlinks, so imports copy instead.

Effect: while a torrent seeds, it uses double the space. When seeding hits ratio 1.0, qBittorrent stops it and the *arr removes the torrent copy (Remove Completed is on).

If disk space or speed becomes a problem, move data\ into the WSL2 filesystem, where hardlinks work.

Security & privacy

What protects you, and how it was verified.

✓ IP never exposed to peers

qBittorrent's public IP is Surfshark's (Amsterdam), not the home IP. Checked from inside the container.

✓ Kill switch

Stopping gluetun left qBittorrent with no network at all, so nothing can leak if the tunnel drops.

✓ Double bind

qBittorrent is also locked to interface tun0, so it can't use another interface even if misconfigured.

✓ Every UI has a login

Forms login on the *arrs, qBittorrent password, Jellyfin accounts for Jellyfin & Seerr.

✓ Apps use API keys

Service-to-service calls use per-app API keys, so changing a login doesn't break the connections.

✓ Secrets in one file

.env holds the WireGuard key and passwords. Never share or commit it.

Surfshark has no port forwarding, so qBittorrent shows "firewalled". Downloads work fine; you're just less connectable on private trackers (slower ratio building).

Lessons learned during setup

Problems hit while building this, and how each was fixed. Useful if something breaks later.

“localhost” inside a container is the container

Seerr couldn't reach Jellyfin at localhost:8096.

Fix: use container names (jellyfin, radarr, gluetun) in app settings.

ISP blocks torrent sites

ACT broke SSL handshakes to EZTV, Nyaa, 1337x and others.

Fix: Prowlarr's global proxy → gluetun:8888; FlareSolverr moved into gluetun.

Jellyseerr can't log in to Jellyfin 12

Jellyseerr 2.7.3 is deprecated; Jellyfin rejected its login (request.App null).

Fix: replaced with its successor, Seerr.

qBittorrent saves settings lazily

UI changes were lost when the container was recreated.

Fix: after changing settings, docker restart qbittorrent (graceful stop writes the config).

Five wrong logins = 1-hour ban

qBittorrent banned the host IP (HTTP 403) after failed logins; Radarr/Sonarr broke when the password changed only in the UI.

Fix: .env is the source of truth; restart clears bans.

gluetun restart orphans its dependents

Containers sharing gluetun's namespace lose networking if gluetun is recreated.

Fix: docker compose up -d --force-recreate qbittorrent flaresolverr.

“No results in configured categories”

Radarr refuses indexers whose recent-uploads feed has no movies (TPB, LimeTorrents).

Expected. They still serve Sonarr; Knaben covers them for movies.

A new library isn't scanned automatically

The test movie was imported before its Jellyfin library existed.

Fix: one manual scan; after that, *arr → Jellyfin "Update Library" handles it.
